| 2026-10-10 | `eval_cp` convention, for every `eval_source`: **eval of `fen_before` (position BEFORE the move), White's point of view, centipawns**. | 2026-10-10 | Repair existing data by re-parsing + restoring Stockfish-only evals from a backup, not by an in-place migration that shifts Lichess evals by one ply | Re-parsing exercises the actual fixed code instead of a second implementation of the same shift that could drift from it, and it removes two migration risks: double-run (shift applied twice, silently) and mixed-source games. Result: 806,042 / 806,464 rows with an eval (the 422 gaps are Lichess ply-1 rows and gaps shifted by one ply; none are wrong values). |
| 2026-10-10 | V2 model: drop `ply` from `FEATURE_COLUMNS`, keep `move_number`. **Deviates from spec line 253**, which lists both. `ply` stays in `dataset.py` for sorting and the `ply > 10` filter. | On my-moves-only rows, `ply = 2 × move_number − 1` (White) or `2 × move_number` (Black): same information twice, and the model split the importance between them arbitrarily (they swapped places between two early runs). `ply` also encodes my color through its parity, but a tree only makes threshold cuts and cannot read parity — if color matters, add an explicit `my_color` feature instead. `move_number` kept because it is the number humans read ("move 25") and the unit V1's M1 fatigue curve is bucketed by. Result: `move_number` SHAP 0.041 → 0.119 (≈ the former 0.087 + 0.041 sum), PR-AUC 0.138 → 0.134 — inside the ±0.025 CI, and changing the column set alone reshuffles `feature_fraction`'s column sampling, so single-run deltas of a few thousandths are noise. |

V2 blunder-risk model (current regime, temporal split, test = most recent 15% of
games, base rate 5.05%) — first run on correct labels, 2026-10-10:

V1. **LightGBM clearly beats the baseline** (spec line 277 checkpoint met). Current feature set (after the `previous_long_think` leak fix and `ply` removal): LightGBM PR-AUC 0.134 (CI 0.113-0.162) vs baseline 0.105 (0.089-0.127); random = 0.05. The separate CIs overlap, but the **paired** game-level bootstrap on the difference gives **Δ = +0.029, 95% CI [+0.012, +0.047]**, LightGBM ahead in 1000/1000 resamples (≈ +27% relative). Pairing works because both models are scored on the same resampled games, so the shared easy/hard-sample variation cancels. Caveat: one temporal test block (~300 most recent games) — "beats it on my recent games", not a guarantee on future ones.
V2. Calibration usable: mean predicted ~6.0% vs 5.05% actual (~1.2x). Top risk decile blunders **14.7%** of the time (~3x base rate), bottom decile 0.16%.
V3. Top SHAP drivers: `material_imbalance`, `eval_volatility`, `clock_before_move_pct`, `eval_before_move`. Ranking barely changed after the label fix. **Do not interpret `material_imbalance` / `eval_before_move` yet**: blunder = win% drop ≥ 20, and the win% curve is steepest near equality, so part of their weight may reflect the measurement scale rather than my play — check dependence plots first.
Main (blitz+rapid) findings, revised on the full ~9,200-game Lichess+chess.com
combined dataset — supersedes the 2026-08 baseline below.

1. Fatigue curve, revised: blunder rate ~0.3% (early) → peak **6.4-6.8% around move 15-20** → decline to ~1-2% by move 65-80. Peak moved earlier than the original ~move 30-40 estimate now that the survivorship-bias-controlled (n_plies≥40) and unfiltered curves agree on the same location. Complexity-vs-move-number test still not run.
2. Time→blunder signature, stable under 3.5x the sample: 3.72x ratio (16.5% vs 4.4% baseline), n=4,414 long-think instances (730 followed by a blunder within 3 moves). Essentially unchanged from the 3.77x baseline estimate.
3. Conversion leak, revised down: 72.6% conversion rate from win% ≥ 80 (n=4,512 games, blitz+rapid, up from n=1,155) — more than 1 in 4 "should-win" positions thrown, a bigger leak than first estimated. Median 30 plies to finish (24 for converted wins). Correction (2026-08): an earlier pass reported 70.7%/n=7,024 for this row — that figure was actually main+bullet blended together, not main alone (`m3_greed_conversion` is deliberately unsplit by perf_group, and the post-hoc "main" filter was missed when first computed). Caught via a mismatch against the new Actual Me dashboard page.
4. Time pressure (move ~67 onset) and the blunder peak (move 15-20) — the gap is wider than the original estimate (56 vs 30-40) suggested, reinforcing these as separate failure modes.
5. Opening mismatch, reversed again: Sicilian as White is now 51.8% (n=613, up from n=185) — no longer a finding, essentially break-even. Italian as Black is now 45.0% (n=200, up from n=47, ±6.9pt 95% CI) — now the better-supported hypothesis of the two, still below 50%. Opponent-strength confound re-checked and still doesn't explain either number away (both sets of opponents weaker than my pool on average).

Bullet findings (new, `perf_group == "bullet"`, 2,512 qualifying games for M3):

B1. Sharper, earlier blunder peak than main: ~11.7% around move 15 vs ~6.8% for main — noisier estimate (smaller per-tercile samples), despite bullet being the player's strongest time control by peak rating.
B2. Time→blunder ratio 3.82x (vs 3.72x main) — signature holds even under a compressed clock.
B3. Conversion worse than main, not better: 67.3% (n=2,512) vs 72.6% (corrected, see main finding #3) — a real tension with the peak-rating gap, a 5.3-point gap. Median 32 plies to finish (28 for converted wins).
B4. Time pressure onset at move 54 (vs 67 main) — expected from the shorter base clock, included as an M4 sanity check.
